# Evaluation and capacity

Evaluation lives in two places: the CI release gate before promotion, and routine operations after the corpus, model, prompt, or retrieval changes. The portal shows the report. `rag-evaluate` runs the dataset. A chunking change creates a new index version. An embedding, dimension, or digest change must reindex. An incompatible old embedding configuration is rejected, so the system does not silently search with a different vector.

Baseline gate: every security case must pass. The example golden set requires a 100% pass. For company questions, set the accuracy target with the knowledge owner. Do not treat the three example questions as a representation of the corpus. Keep tuning, regression, and holdout datasets separate. Use real questions that have been anonymized, plus answers and source spans reviewed by a subject-matter expert. Include revoked permissions, a different tenant, a document past retention, injection inside a file, an ambiguous question, a table, Indonesian language, and a conflict between versions.

Automatic checks: expected status, abstention, important words and amounts, allowed and required sources, exact quotation on the server, source IDs, and inline citations. An exact quote proves the citation exists in the source chunk. It does not prove that every claim in the answer is supported. A human reviewer scores factual correctness, faithfulness, completeness, citation relevance, and the acceptable error rate. User feedback is an investigation signal, not an automatic correctness label. An evaluation an admin posts to the API is not cryptographic CI evidence. A promotion decision must read the artifact from the protected pipeline.

Store the model digest, the LightRAG and dependency lock, the dataset revision SHA256, the release revision, the prompt revision, and the retrieval profile. Production datasets stay on storage with a company ACL. Reports do not store raw questions or answers by default, only case IDs and checks.

Load test with `k6 run eval/load.js` and the environment variables `BASE_URL`, `EVAL_TOKEN`, `TENANT_ID`, `DOCUMENT_ID`, `USERS`, and `DURATION`. Do not put the token in command history. The default threshold of p95 under 60 seconds and HTTP failure under 1% is only a starting example, not a verified SLO. Measure 1, 5, 10, and 20 concurrent users, corpora of 100, 1,000, and 10,000 documents, latency per mode, ingestion throughput, GPU VRAM and queue, PostgreSQL connections, CPU, and IO, and embedding size. Test queries and ingestion together, and the loss of the model or GPU standby. Report p50, p95, and p99, timeouts, 429s, and quality at peak load.

A 4096-dimension embedding with an exact scan and per-document workspaces has a cost that must be measured. The default query limit of 20 documents and the semaphores intentionally limit GPU use. For a large corpus, add permission-aware catalog routing and/or an evaluated index adapter. Do not raise the limit without a capacity test. When retrieval changes, compare results on the same corpus snapshot and repeat the holdout and security suite before promotion.
